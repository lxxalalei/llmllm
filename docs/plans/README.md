# 开发计划约定

本目录只用于需要跨模块、跨里程碑或跨会话延续的有界实施计划。项目级路线和下一验收项始终以 [`docs/roadmap.md`](../roadmap.md) 为准；小型明确改动不需要创建计划文件。

当前活动计划只能从 roadmap 的“当前路线”进入。已完成或被替代的计划由 [`archive/README.md`](archive/README.md) 索引；归档文件只保存历史决定和验证证据，不得继续声明自己是当前路线。

## 何时创建计划

满足任一条件时，在本目录创建 `<主题>.md`：

- 工作跨越多个模块或独立里程碑；
- 工作需要由多个所有者协作并明确依赖；
- 工作无法在当前会话内完成，需要可靠接手；
- 验收包含多种测试层级或真实用户流程。

计划不得复制能从 PRD、架构文档、代码、Git 或 roadmap 直接获得的内容，只记录本次实施所需的边界、决定、状态和证据。每个计划必须从 `docs/roadmap.md` 的对应路线链接进入，避免成为孤立事实来源。

## 状态与主路线

状态词与含义统一采用 `docs/roadmap.md` 的定义。默认只有当前主路线及其对应计划可以是 `in_progress`。并行计划必须在 roadmap 中标明各自所有者、文件范围、依赖关系和独立验收条件。

计划受阻时，记录缺少的输入或外部条件、已有证据和解除条件；不能因为工作困难或测试尚未完成而标记 `blocked`。

## 收口与归档

1. 验收全部满足后补齐实际验证证据、未验证项和剩余风险。
2. 更新 `docs/roadmap.md` 的路线状态、下一验收项和相关链接。
3. 已完成或被替代且不再是日常入口的计划移动到 `docs/plans/archive/`，并登记到 `docs/plans/archive/README.md`。
4. 归档后修复所有链接。只有调查历史决定或回归来源时才读取归档计划。

交接文档不是新的事实来源；接手者仍需以当前代码、Git 状态、项目规则、roadmap 和活动计划重建实时状态。

## 下一轮规划检查点

每个计划级或迭代级任务完成后，必须在更新 roadmap 和归档之前判断下一轮：

1. 用户已指定后继任务：创建或更新对应计划，并将它设为当前主路线。
2. 验收证据只导向一个明确后继目标：可以主动创建下一计划，并与前序计划相互链接。
3. 存在多个会改变产品、架构或优先级的方向：不替用户选择；在 roadmap 记录候选和决策缺口，等待用户决定后再建计划。
4. 没有具体后继目标：明确记录“当前无下一轮计划”，不为维持流程制造任务。

新计划继续使用本项目现有的 `docs/plans/<主题>.md` 命名和索引方式，不另建 `.agent/` 或第二份 roadmap。
